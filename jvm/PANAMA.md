# Java 25 Panama integration and optional Spinel C API compatibility

Status: implementation design, 2026-10-21. Required FFI/native-binding work is
planned here; it is not implemented by the current JVM backend. The broader C
extension API in the last section remains an open, optional compatibility
project. No native library, JDK component, or dependency was installed during
this planning work.

## Policy and scope

- Target Java 25's final `java.lang.foreign` API. No preview flags, internal
  Unsafe access, libffi runtime, or new JNI bridge is required for normal calls.
- Implement existing `ffi_*`, supported FFI-gem-shaped declarations, and
  `native_*` carried-package bindings. Preserve the source vocabulary where its
  contract is representable; report unsupported declarations explicitly.
- Prefer JDK APIs for ordinary IO, files, sockets, clocks, processes, and other
  OS facilities. Panama supplies missing capabilities or calls to libraries
  explicitly selected by the program; it is not the default implementation of
  every POSIX operation. Fork, native GC control, and native stack unwinding are
  out of scope.
- A C library can own native memory; it cannot inspect JVM objects or the JVM
  heap. Passing an object uses an opaque handle or an explicit copy, never a
  Java object address. Java record/value-class layout is never a C ABI.

The [Java 25 FFM guide](https://docs.oracle.com/en/java/javase/25/core/foreign-function-and-memory-api.html)
describes the public API. FFM enforces some access/lifetime checks but cannot
make an incorrect native signature, arbitrary pointer, or buggy C library safe.
Native integration remains a trusted capability.

## Current source contracts that need exporting

`src/compiler.h` and `src/ffi_spec.c` already describe substantially more than
the counts currently exported by `src/backend_ir.c`:

- `ffi_func`: namespace/name, actual C symbol, argument/result specs, blocking.
- Libraries, constants, buffers, read/write accessors, callbacks, structs and
  fields, compile flags, and inline C source.
- `native_func`, `native_lib`, `native_obj`, `native_struct`, `native_new`,
  `native_method`, object ownership/free functions, and reflection requirements.

Export these as validated declarations with source locations and requirement
origins. Add explicit ownership, retained-pointer/callback, mutability, and
thread-affinity metadata where existing declarations do not convey enough.
Extend declaration options compatibly; do not infer unknown ownership from a
function's name or silently select an unsafe default.

Use the actual type table and tests as the contract. In particular, the old
`docs/FFI.md` table describes `:bool` as C int, but current
`src/ffi_spec.c`, `ffi_bool_return_low_byte.rb`, and
`native_bool_return_width.rb` require C `_Bool`. Keep FFI C `int` distinct from
native-binding `sp_int`, which is `intptr_t` in this source revision.

## Required implementation stages

### P1. Scalar calls, library resolution, and ABI validation

Generate a typed binding class with cached symbol lookups, descriptors, and
`static final MethodHandle` downcalls. Invoke exact primitive/MemorySegment
signatures from generated bytecode or a generated typed Java stub. Avoid
`invokeWithArguments`, per-call descriptor construction, reflective invocation,
and native-library loading in the hot path.

| Source contract | Boundary representation |
| --- | --- |
| C signed/unsigned fixed-width integer | Exact-width carrier plus explicit signed/unsigned conversion |
| C `int`, `long`, `size_t`, `_Bool` | Host C ABI layout; do not assume Java long equals C long |
| `float` / `double` | Java float / double at the downcall, explicit Spinel conversion |
| Pointer / nil | MemorySegment / NULL, with ownership and bounds metadata |
| Void | Void descriptor, not a fabricated value slot |
| Primitive-or-BigInteger value | Convert the record carrier to the declared C contract explicitly |

Use the native linker's
[canonical layouts and downcall descriptors](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/foreign/Linker.html)
and native compiler probes where a typedef or aggregate requires them. Check
LP64 versus LLP64, alignment, byte order, padding, and supported architectures.
Preserve declared C narrowing/cast semantics rather than accidentally applying
Java overload conversions. Full-width unsigned results need an explicit numeric
policy; never confuse their bit pattern with a JVM object handle.

`ffi_lib` resolves a declared shared library, not a `.a`/`.o` as a loadable
image. Use explicit package paths or configured system lookup; record actual
library identity and platform requirements. Native library trust and native
build trust are separate from merely having a Java JAR on the classpath.

Tests: libc/libm arithmetic and strlen, renamed symbols, fixed-width loads,
`_Bool` return/argument width, large inputs, nil pointers, missing libraries,
missing symbols, and incompatible descriptors. Declaration-only fixtures such
as `ffi_array_specs_decl.rb` may contain unreachable nonexistent symbols: load
and link only reachable declarations, with an explicit eager-validation mode
if desired.

### P2. Buffers, strings, arrays, pointers, and structs

- `ffi_buffer` uses a managed native allocation with the declared program
  lifetime. Field readers/writers use explicit layouts and checked slices.
  Preserve compile-time bounds diagnostics and runtime bounds checks.
- `ffi_struct` uses target-ABI layout including padding; generate C probes for
  `sizeof`, alignment, and offsets where necessary. String/pointer fields retain
  the relevant resource owner, not a temporary allocation that has already died.
- `:str` is copied to a temporary NUL-terminated native buffer. Copy borrowed
  returned text before its owner can invalidate it; free owned results with the
  declared matching allocator. Embedded-NUL truncation is specific to this C
  string contract, not general Spinel String behavior.
- Preserve `:binstr`'s binary-safe result with an explicit length result/out
  parameter in a tiny C adapter. Do not reproduce the native runtime's global
  `sp_ffi_bin_len` scratch channel in a concurrent JVM. Legacy helper calls
  must have adapters returning the pointer and length for that invocation.
  Until rebuilt with per-call storage, serialize a legacy call and scratch
  retrieval together so another native worker cannot overwrite the length.
- Marshal numeric arrays to native storage with declared read/write direction.
  Existing callback-driven mutations, such as qsort, require ordered copy-back
  into the same Ruby array identity. Test overlapping/aliased arguments and
  define cleanup/copy-back behavior on errors and cancellation.
- Use explicit borrowed/shared native-buffer objects for genuinely retained or
  zero-copy memory. Do not imply that ordinary heap arrays expose a stable C
  address, or that a pointer can be retained beyond a temporary call scope.
- Preserve null and documented integer pointer sentinels, including zero and
  library-specific all-ones markers, without treating an unbounded raw address
  as a safe dereferenceable segment. Address reinterpretation is a restricted,
  checked-at-the-boundary operation with declared provenance/size where known.

Choose [Arena lifetimes](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/foreign/Arena.html)
explicitly: confined per-call scratch, shared closeable scopes for resources
used by multiple virtual threads, and a package lifetime for retained symbols
and buffers. Native resource owners must support deterministic close with
idempotence, in-flight operation tracking, and use-after-close checks. Cleanup
must not depend on an application requesting a JVM collection.

### P3. Callbacks, errors, and blocking native work

- `ffi_callback` creates a typed FFM upcall stub into compiled Spinel code.
  Keep the callable, runtime context, and arena alive for the registration's
  entire lifetime; unregister before releasing them. Distinguish call-duration
  callbacks from callbacks retained by C.
- Catch **all** throwables at the FFM upcall boundary, store a pending failure
  in the invocation/registration context, and return the declared C error value
  or adapter status. Re-raise the original Java/Spinel exception after native
  control returns to a safe Java boundary. A callback must not let an exception
  escape through C: the [Linker upcall contract](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/foreign/Linker.html#upcallStub(java.lang.invoke.MethodHandle,java.lang.foreign.FunctionDescriptor,java.lang.foreign.Arena,java.lang.foreign.Linker.Option...))
  warns that an escaping exception can terminate the JVM.
- Never `longjmp` through a Java frame, throw a Java exception across C, or
  assume a legacy C `sp_raise_cls` can unwind an FFM downcall. A native adapter
  catches legacy native errors entirely within C and returns a status.
- Capture errno immediately with the linker's supported call-state option and
  map failures into readable JVM exceptions. Do not read errno later on a
  possibly different native carrier. Preserve the original exception cause.
- Long blocking foreign calls can pin virtual-thread carriers. Offload to a
  bounded platform-thread executor when affinity permits; create confined
  buffers on that worker or use shared scopes. A worker completes the native
  call before resources close, even if its waiting fiber times out. Respect
  libraries requiring one dedicated OS thread or same-thread callbacks.
- Synchronous callbacks reenter through an explicit invocation context and
  reentrancy/ownership protocol. Asynchronous foreign-thread callbacks require
  explicit attachment/dispatch to a Spinel context, retained handles, and a
  documented concurrency policy; they do not inherit the original fiber's
  Java ThreadLocal state magically.
- Initially reject fiber yield/transfer across a live native callback frame
  with a clear error. Ordinary Java-frame suspension is supported by the fiber
  model; suspension across C requires an explicit asynchronous native protocol
  or a separately validated pinned-thread policy, not arbitrary stack capture.
- Do not apply `Linker.Option.critical` to ordinary FFI. Consider it only for
  measured, extremely short, nonblocking, non-callback functions that satisfy
  the API contract. It is not a solution to retained heap pointers.

[Call-state capture and critical-call restrictions](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/foreign/Linker.Option.html)
and [virtual-thread carrier pinning](https://docs.oracle.com/en/java/javase/25/core/virtual-threads.html)
are runtime constraints, not new Spinel GC features.

### P4. Carried C and `native_*` objects

Build trusted `ffi_source` fragments and carried sources as PIC shared
libraries. Reuse `spin`'s declared-native-build trust gate, dependency manifests,
and caching; include source, toolchain, flags, architecture/OS, and ABI version
in the cache key. Do not try to load a native-backend `.o` directly or assume a
precompiled object is independent of its native Spinel runtime layout.

Keep the ordinary native data object in C as an opaque resource handle. A Java
owner mediates constructors, methods, close/free, and pending operations. Use
typed scalar/byte-buffer shims where a package's original signature exposes
`sp_RbVal`, GC strings, arrays, or native object internals. Do not bundle a
second Spinel collector simply to make native heap layouts appear compatible.

Start with one minimal carried class covering constructor, scalar methods,
binary string output, explicit free, and use-after-close. Then adapt package
bindings by dependency edge: StringIO/strscan/JSON-like packages demonstrate why
ordinary downcalls alone do not recreate the current C runtime ABI. A JDK-backed
OS implementation is preferred where appropriate, but C libraries explicitly
required by programs still need the FFM binding path.

## Build, launch, and access policy

Extend `spin.toml`'s JVM configuration with structured native-library/source,
platform, and trusted-build metadata. Carry required native access into
`spin run` and generated launch instructions; do not silently grant it to every
Java-only program. For the current classpath packaging, a native application
will need an explicit grant such as:

```sh
java --enable-native-access=ALL-UNNAMED --illegal-native-access=deny -jar app.jar
```

For a future named runtime module, grant the smallest module that owns the FFM
operations instead. These flags are defined by the
[Java 25 launcher](https://docs.oracle.com/en/java/javase/25/docs/specs/man/java.html).
They enable native access, not a sandbox for untrusted C.

Do not assume the `java.library.path` mechanism is identical to an explicit
FFM `SymbolLookup.libraryLookup` policy. Keep library search paths separate from
Java classpaths. Pure-JVM builds must not require a C compiler or native-access
grant; native builds must identify their toolchain, platform, and dependencies.

## Optional Spinel C extension API compatibility

This option remains open. It follows the required FFI stages; it is neither a
blocker for them nor a promise that arbitrary existing binaries will load.

### Three distinct integration directions

1. Load a C package written against a supported subset of Spinel's C API into a
   running JVM. Recompile/adapt it against a compatibility header and use FFM
   downcalls/upcalls plus opaque handles.
2. Call a native-compiled Spinel kernel exported by `--ext-init`/`--ext-entry`
   from JVM code. Wrap its existing initialization, typed entries, copied
   strings/arrays, and native try helper behind a narrow C status-returning
   adapter. Its native heap remains its private implementation detail.
3. Expose JVM-compiled Spinel entry points to C as registered FFM upcall function
   pointers while the JVM and registration remain alive. FFM does not bootstrap
   a JVM into a standalone C process; that hosting question is separate. This
   proposal does not implement a CRuby `ruby.h`/VALUE/GVL compatibility layer.

### Proposed narrow ABI

Use fixed-width scalar fields, opaque per-context handles, explicit byte spans,
status returns, and out parameters. Start with one exported registration symbol
and a size/versioned callback table; add only operations a supported package
actually needs. A schematic entry point is:

```c
typedef uint64_t spj_handle;
typedef struct spj_host_v1 spj_host_v1;

int32_t spinel_jvm_extension_init_v1(
    const spj_host_v1 *host,
    uint64_t context,
    spj_handle *out_error);
```

The host table begins with ABI version, structure size, and capability bits.
Its initial operations cover method registration/invocation, checked scalar
conversion, copying bytes, the minimum array access needed by the pilot
package, exception creation, and explicit retain/release. Function signatures
and ownership are part of the versioned header, not guessed from JVM internals.

Opaque handle rules:

- A handle is not an object address. Validate context and generation so stale,
  foreign-context, and double-released handles fail safely.
- Temporary handles belong to an invocation scope; retained handles hold
  explicit strong Java references until released. C never sees JNI references,
  a GC root pointer, a record layout, or a Java class's field offsets.
- Resource identity lives in an owner object/table, separate from immutable
  record values. Promoted integers and other value-doubles can change internal
  representation without changing the C ABI.
- Bytes cross as pointer plus explicit length and ownership. Caller-owned
  buffers or library-owned buffers with an explicit release operation avoid
  allocator mismatch and NUL-termination ambiguity.
- C errors return status plus an error handle; Java callbacks capture pending
  exceptions and return normally to C. No cross-language `setjmp`/`longjmp`.

### Compatibility limits and pilot

`lib/spinel/runtime.h` currently includes native value, allocation, and GC
headers. Its apparent C layouts are not a bridge to the JVM. A supported source
subset can be recompiled using a distinct compatibility header or opt-in build
define. Packages accessing `sp_RbVal` fields, GC string headers, native array
structs, collector functions, or `sp_raise_cls` nonlocal unwinding need adapters
or source changes; unchanged binary compatibility is not claimed.

Where safe, legacy root-scope macros may become handle-scope retention helpers,
not collector controls. Collector hooks, heap walking, raw JVM object pinning,
and GC counters remain unsupported. Native allocation ownership still requires
an explicit close/free protocol.

Pilot sequence:

1. Publish an experimental versioned header and ABI conformance library.
2. Register one C-backed scalar method, a byte-string round trip including NUL,
   a mutable-array operation, and one stored opaque native object.
3. Add exception round trips, callback registration/unregistration, retained
   handles, nested reentry, and deterministic close under virtual threads.
4. Adapt one real carried package; measure boundary crossings and copied bytes
   before expanding the API. Prefer bulk operations over per-element upcalls.
5. Separately wrap `test/ext/kernel.rb`'s native exports, preserving parameter
   copy/mutation rules and its native try boundary. Add JVM-to-C upcall exports
   only with a clear lifetime/hosting contract.

Acceptance includes stale-handle rejection, arena lifetime errors, native
resource leak checks, exact boolean/integer widths, failure without native
access grants, bounded callback error handling, concurrent contexts, and a
small demonstrated package migration. No Spinel GC metrics or native stack
trace fidelity is part of the acceptance contract.
